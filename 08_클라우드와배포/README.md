# PART 4 — 클라우드와 데이터베이스

PART 3(백엔드)에서 만든 서버를 **진짜로 배포**하는 과정입니다.

파일에 저장하던 것을 데이터베이스로 옮기고, 그 데이터베이스를 클라우드로 옮기고,

마지막으로 그 서버에 **진짜 로그인**을 붙입니다.

## 실측으로 뒤집힌 것들

자료의 모든 출력은 실제로 실행해서 얻은 값입니다.
쓰는 동안 감으로 적었다가 측정에 뒤집힌 것들입니다.

| 무엇 | 처음 생각 | 실제 |
| --- | --- | --- |
| `STRICT` 와 타입 | 숫자→글자 거절 | 무손실 변환은 통과. `123`→TEXT 는 `"123.0"` |
| `node:sqlite` 외래키 | 기본 꺼짐 | **기본 켜짐** (다른 SQLite 자료와 반대) |
| `prepare()` 와 세미콜론 | 두 문장 다 실행 | **첫 문장만**. `exec()` 는 전부 |
| `LIMIT -1` | 0건 | **전부 반환** |
| 정렬키가 겹칠 때 | 안전 | 같은 줄이 **두 쪽에** 나옴 |
| `NOT IN` + 서브쿼리 NULL | 정상 | **0건** (오류 없음) |
| 색인 효과 (20만 줄) | — | 1810ms → 1ms (**1810배**) |
| N+1 | 크게 느림 | 로컬 3배, **망 왕복 3ms면 200배** |
| PM2 `reload` | 실패 0건 | 여러 번 재니 **ECONNRESET 2건** |
| 윈도우 클러스터 | 골고루 분배 | 8요청이 **한 워커로** |
| `trust proxy` 없이 | IP 가 보임 | **전부 `127.0.0.1`** |
| Git Bash `chmod` | 권한 바뀜 | **안 바뀜** (644 유지) |

★ PM2 무중단 재시작은 처음 한 번 쟀을 때 실패 0건이 나왔습니다.
부하와 명령이 같은 프로세스라 측정이 측정을 방해한 것이었습니다.
**한 번 재고 결론 내리면 안 됩니다.**

## 검증 도구

```bash
node _검증도구/전체검증.js        # 아래를 전부
node _검증도구/출력검증.js        # 주석의 // 출력: 과 실제 실행 결과 대조
node _검증도구/서버검증.js        # 서버를 띄우고 // 확인: 대로 요청
node _검증도구/화면검증.js        # 진짜 크롬으로 // 화면: 대로 눌러 봄
node _검증도구/정합성검사.js      # 선언 문법·짝 확인
```

**지금 상태**

```
출력 대조   70파일 / 0불일치      (Node 24 기준)
서버 요청   28건 / 0실패
화면 대조   건너뜀 — `// 화면:` 선언이 아직 없습니다
정합성      81파일 / 0건
```

★ 화면검증은 크롬을 띄워 `// 화면:` 선언대로 눌러 보는 도구인데,
이 자료에는 아직 그 선언이 없어서 **건너뜁니다.** 전체검증이 `－ 건너뜀` 으로 표시합니다.
"건너뜀" 은 통과가 아닙니다. 검사를 안 한 것입니다.

### 선언 문법

```js
console.log(1 + 2);
// 출력: 3

console.log("걸린 시간:", 재기().ms, "ms");
// 출력?: 걸린 시간: 1810 ms      ← 값은 안 보고 줄만 확인 (기계마다 다름)
```

```js
// 확인: GET /equipments
// 응답: 200 {"data":[]}
```

- `// 출력:` 은 **다음 줄에 단독으로** 씁니다
- `// 출력?:` 은 측정값처럼 기계마다 다른 줄에
- `// 확인:` 은 반드시 `확인: METHOD /경로` 형태여야 선언으로 봅니다
- `// 이파일은끝납니다` 를 맨 위에 적으면, `.listen` 이 있어도 출력검증이 실행합니다
- `// 화면:` 은 `// 보임:` 과 짝으로 씁니다 (화면검증)
- `// 검증무시:` 를 줄 끝이나 바로 윗줄에 적으면 그 줄은 검사에서 뺍니다
  - "이렇게 하면 안 됩니다" 를 보여 주는 코드에 씁니다 (배포점검·정합성검사)

★ 도구가 오탐을 내면 **도구를 고칩니다.** 이 자료를 만들며 다섯 번 고쳤습니다.
